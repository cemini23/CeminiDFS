## Body

### 1. Particle filtering for the late-swap window

Source: `nchopin/particles`, Extract tier.

The eval's own framing: it **"converts static pre-game fantasy projections into dynamic, state-space probability distributions that update continuously based on live drive results, snap counts, and game scripts."**

**That is the late-swap gap.** Today a projection is a number computed before the slate. During the games that number is stale, and the swap decision is made against a stale prior.

A particle filter is the standard tool for this. Maintain a set of weighted hypotheses per player, update the weights as observations arrive, and read the posterior distribution rather than a point estimate.

| Piece | What it does |
|-------|--------------|
| State | Per-player latent usage rate and game state |
| Transition | How usage drifts as the game script changes |
| Observation | Live drive results, snaps, targets, carries |
| Weights | Re-weight particles on each observation |
| Output | A posterior per player, not a point projection |

**Honest caution, and it is the main content of this brief.** This is the highest-complexity item either of the last two waves has produced. Particle filters have real failure modes: particle degeneracy, a misspecified transition model, and a likelihood that looks right but is subtly wrong. **Build it only if the late-swap lane is actually where the margin sits.** If the edge comes from the pre-game projection, this is expensive motion in the wrong direction.

**Suggested first step.** Do not build the filter. Build the measurement: take one past slate, replay the live data, and ask how much a perfect posterior would have improved the swap decisions. If that number is small, stop.

### 2. Permutation tests for overfitting

Source: `neurotrader888/mcpt`, Extract tier.

Shuffle returns and bar sequences to build a synthetic null distribution, then score the strategy against it. A backtest that clears its null by chance looks exactly like one that works.

The eval routed this to the XSP lane. It applies here too: **a projection model or lineup construction whose edge does not survive a permutation test had no edge.** This is cheap to add and it is the kind of check that catches a wrong model before it costs a slate.
