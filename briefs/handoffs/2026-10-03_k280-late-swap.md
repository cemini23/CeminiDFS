## Success criteria

Build ONE new module and ONE new test file. Nothing else in `src/` changes.

1. **`src/ceminidfs/pipeline/late_swap_replay.py`** exists and runs as
   `.venv/bin/python -m ceminidfs.pipeline.late_swap_replay`.

2. **Field availability ledger.** A module-level table maps each input field to
   the instant it becomes observable: `kickoff` and `fd_projection` are pre-game;
   live drive/snap/target/carry counts accrue only from plays already run;
   `fd_actual` (final points) becomes observable only at the end of that game.

3. **Leak guard.** A function `assert_no_future(field, observed_at, decision_time)`
   raises `ValueError` when `observed_at > decision_time`. Every field read inside
   a swap decision passes through it. The decision time is the gate.

4. **`live_projection_as_of(player, decision_time)`.** Returns a point estimate
   from plays already run at that instant. For a player whose game has not kicked
   off, there are no live plays, so the value falls back to the pre-game
   `fd_projection`. Never reads `fd_actual`.

5. **`replay_leak_free(seats, pool, decision_times)`.** At each decision time:
   lock every player with `kickoff <= decision_time` (frozen, cannot be removed);
   re-optimize only the unlocked seats using `live_projection_as_of`; keep salary
   in `[$58,500, $60,000]`; keep the FanDuel slot rules from the oracle module.

6. **The money output.** The module prints, for the W3 book:
   - `held_points` — the book as filed.
   - `leak_free_points` and `leak_free_gain` — the no-leak replay result.
   - `swappable_players_with_live_data` — how many UNLOCKED players had any live
     play available at any decision time. This is the load-bearing number.
   - `hindsight_ceiling_points` — re-read from `late_swap_oracle.measure_default_slate()`.
   - `foresight_share` = `(hindsight_ceiling - leak_free) / (hindsight_ceiling - held)`
     when the denominator is non-zero, else `n/a`.

7. **Report.** Append a `## Leak-free replay` section to
   `briefs/2026-10-03_k280-measure.md`. Do not clobber the existing
   `## Permutation test` section. State the STOP/GO line in plain words: if the
   leak-free gain is small, do not build a particle filter.

8. **`tests/test_late_swap_replay.py`** with at least:

## Plan

Goal: measure the late-swap upside with zero future information in any swap
decision, then decide GO/NO-GO on the particle filter.

1. Keep `late_swap_oracle.py` untouched as the HINDSIGHT CEILING. Its banner
   already says `live_information_only=false`; that flag is the warning label.

2. Add `late_swap_replay.py`. The design is a decision-time gate:
   - The lock rule is `kickoff <= decision_time`. It is already correct in the
     oracle module; reuse it.
   - The leak rule is `observed_at <= decision_time` for every field.
   - The two rules mean: at each wave, the games that supply live data are
     exactly the games that are locking. So an unlocked player has no live data.
     The `swappable_players_with_live_data` counter measures that claim.

   Report the gain from held to leak-free, and the `foresight_share` of the
   ceiling above the leak-free result.

   late-swap lane carries no live edge on this slate shape. STOP. Say so.
